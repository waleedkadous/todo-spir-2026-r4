## **KEY_ISSUES**

### Issues (Non-blocking)

1. **Empty state message doesn't differentiate "no todos at all" vs. "no todos match filter" (Minor)**
   - `TodoList.tsx` (line 17-18) always shows *"No todos yet / Add your first todo above"* regardless of whether the empty state is caused by no todos existing or by filters hiding all results. The plan explicitly calls out: *"Empty state messaging"* as a deliverable, and the spec acceptance criterion says *"Empty state shown when no todos match filter."*
   - **Recommendation**: When `todos.length > 0` but `filteredTodos.length === 0`, show something like *"No todos match the current filters"* with a "Clear filters" link. This could be done by passing a `hasFiltersApplied` or `totalCount` prop to `TodoList`, or by handling it in `page.tsx` above `<TodoList>`.

2. **No "clear/reset filters" affordance (Minor)**
   - Users can set filters via dropdowns but there's no quick way to reset both filters back to "all". This is low-effort UX polish that fits naturally in the FilterBar.

3. **`globals.css` has no additional responsive styles (Observation)**
   - The plan lists *"src/app/globals.css — Additional responsive styles"* as a file to modify, but it remains untouched (just the three Tailwind directives). In practice, the responsive behavior is handled entirely via Tailwind utility classes (`flex-wrap`, `sm:` breakpoints in `page.tsx`), which is perfectly valid — no custom CSS is needed. This is a plan deviation in letter but not in spirit.

4. **"Visual polish (sorting, priority colors, overdue indicators)" partially delivered (Observation)**
   - The plan deliverable mentions sorting, priority colors, and overdue indicators. Priority colors and sorting appear to be handled in Phase 2 components (`TodoItem`). Overdue indicators are not visible in any Phase 3 file. This may be acceptable as a v1 cut, but it's worth noting for completeness.

5. **`FilterBar` count shows "0 todos" for zero state, not "0 of N" (Nitpick)**
   - When `filteredCount === 0` and `totalCount > 0`, the display shows `"0 of 5"` which is correct. When `filteredCount === 0` and `totalCount === 0`, it shows `"0 todos"` — also correct. The singular/plural logic (`totalCount !== 1`) is properly handled. No issue here, just confirming it was verified.
